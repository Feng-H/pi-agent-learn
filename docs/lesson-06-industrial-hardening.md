# 第六讲复盘：工业级防线硬化与 CMU AI Agents 体系对标

> “从玩具 Demo 到工业级铠甲，差的往往不是花哨的功能，而是对底层协议物理现实的绝对敬畏与防御性死角消除。”

本篇文档记录了我们在第六阶段中，对标 **CMU 11-768 (AI Agents) Assignment 1 · Harness** 工业级要求，针对前期设计在真实生产环境中暴露出的 5 大物理暗坑进行全面防线硬化、重构与全量测试闭环的完整过程。

## 一、背景：为什么需要第六阶段的“工业级硬化”？

在完成了前五阶段（ReAct 循环、双层上下文治理、Pi 风格文件工具、Watchdog 智能方向盘、三级权限闸门）之后，整个系统的核心功能已经齐备。

但在对标国际顶级课程 CMU 11-768 以及更深层的真实运行时审视下，我们发现了 5 个足以让 Agent 在边界条件下直接崩溃或逃逸的物理暗坑：

1. **协议状态机破损（HTTP 400 崩溃）**：看门狗向模型注入警报时，独立推送了一条 `role: "user"` 消息，导致上下文出现连续两条 `user` 角色，违背了 Anthropic 等主流接口严格的角色交替规范；
2. **孤儿工具调用对（Orphan Tool Result）**：在 L2 记忆蒸馏或会话切片时，若切分点恰好落在 `tool_use` 与 `tool_result` 中间，会导致大模型因找不到对应的 `tool_use_id` 而报错中断；
3. **L1 无差别脱水误伤代码真值**：原脱水逻辑仅根据长度（>300 字符）盲目截断输出。当 `read_file` 读取了百行代码后，中间代码在当轮结算时被替换为折叠标记，导致模型在下一轮调用 `edit_file` 时因丢失上下文产生幻觉或匹配失败；
4. **权限闸门的前缀逃逸后门**：原 `PermissionGate` 对安全命令的判定依赖简单的 `startsWith` 前缀（如以 `ls` 或 `echo` 开头）。若模型生成 `echo 'foo' && rm -rf /` 或 `ls; rm -rf .git`，系统会因前缀命中而将其误判为 `SAFE` 绿灯直接放行；
5. **人机协同插话的并发假象**：原 `humanSteeringQueue` 虽有接口，但在单线程交互式 REPL 内部，`runAgentTurn` 执行期间标准输入被阻塞，人类根本无法实时插话。

## 二、五大核心防线重构落地

```text
┌────────────────────────────────────────────────────────────────────────┐
│                 第六阶段：工业级全栈硬化防线矩阵                          │
├─────────────────┬──────────────────────────────────┬───────────────────┤
│ 1. 协议规范器   │ normalizeMessages() 管线         │ 保证交替，孤儿降级  │
├─────────────────┼──────────────────────────────────┼───────────────────┤
│ 2. 工具感知脱水 │ Type-aware L1 Dehydration        │ 保护源码，专折日志 │
├─────────────────┼──────────────────────────────────┼───────────────────┤
│ 3. 完整轮次切分 │ Turn-boundary L2 Distillation    │ 绝不切断工具配对   │
├─────────────────┼──────────────────────────────────┼───────────────────┤
│ 4. 原子语法拆分 │ Shell Tokenizer (&&, ||, ;, |, >)│ 封堵前缀绕过与逃逸 │
├─────────────────┼──────────────────────────────────┼───────────────────┤
│ 5. 非阻塞插话   │ REPL Line Event Steering         │ 运行时随时接管方向 │
└─────────────────┴──────────────────────────────────┴───────────────────┘
```

### 1. 消息管线规范器 (`src/llm.ts`)
在向大模型发起真实网络请求前，增加一层强制归一化拦截器：
- **连续同角色自动合并**：如果连续出现两条 `user` 消息（例如工具执行结果 + 看门狗方向盘警报），自动将其内部的 `ContentBlock` 合流为单条消息；
- **孤儿工具自动修剪**：扫描所有 `tool_result`，若前置 `assistant` 消息中缺少对应的 `id`，将其无损降级为普通标注文本 `[历史工具输出 (已脱敏归档 ID: ...)]`，杜绝接口拒绝。

### 2. 工具类型感知的差异化 L1 脱水 (`src/context-manager.ts`)
脱水程序不再无差别截断，而是反查 `tool_use_id` 识别工具语义：
- **`read_file`（代码真值）**：绝对保护，源码不折叠，保障后续代码修改的绝对精确度；
- **`bash`（终端日志）**：激进脱水，输出超过 400 字符即折叠为首尾切片，单轮立省数百 Token；
- **`edit_file` / `write_file`**：仅保留精简回执。

### 3. Shell 语法树原子拆解与权限闸门升级 (`src/permission.ts`)
废除单纯的字符串前缀匹配，改用原子子命令分解：
- 拦截所有动态命令执行符：`$(...)`、反引号、`<(...)`；
- 依据 `&&`、`||`、`;`、`|` 以及换行符，将复杂命令拆分成独立原子指令；
- 检查重定向操作符（`>`、`>>`），若存在文件写入行为绝不放行只读；
- **全量安全才绿灯**：只有当拆分后的**每一个**子命令均在只读白名单（`ls`, `pwd`, `git status`, `git log` 等）内，且不包含写操作与高危模式时，才授予 `SAFE`；只要任意一个子片段包含破坏性特征，全量提级为 `DANGEROUS`！

### 4. 终端事件级非阻塞人工插话 (`src/index.ts`)
在 REPL 单轮执行 `runAgentTurn` 期间，挂载标准输入的行事件监听器：
- 用户无需等待轮次结束，只要看到 Agent 开始偏航，随时敲入指令按回车；
- 事件监听器实时捕获并在终端打印 `🚨 [人工握紧方向盘]`，将指令注入看门狗队列；
- 在模型的下一步决策前，看门狗以最高优先级弹出用户指令，实现真正的“人在回路（Human-in-the-Loop）”。

## 四、对标 CMU 11-768：我们的工程站位

CMU 课程 Assignment 1 提出的要求是：“Build the harness infrastructure for a coding agent on top of an open-source LLM.”

在经历了第六阶段的硬化后，`pi-agent-learn` 已经从一个验证思路的概念原型（PoC），进化为一套完全满足学术前沿与工业落地的标准级 Harness 底盘：
- **协议容错**：达到工业级客户端的鲁棒度；
- **长上下文治理**：做到了事实保留与 Token 瘦身的动态平衡；
- **安全可控**：具备物理级原子阻断与人类绝对裁决权。
