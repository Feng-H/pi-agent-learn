# 第二讲复盘：长上下文治理与“永不遗忘”的规则体系

> “一个优秀的 Harness，既要能抵御信息的洪流，又要能守住绝对不可侵犯的规则红线。”

本篇文档记录了我们在第二阶段（上下文管理与规则层设计）中，从直觉痛点出发，推导并实现全自动双层上下文治理与规则分层体系的全过程。

---

## 一、核心痛点：Token 的滚雪球效应

在朴素的 Agent 实现中，一旦开启多轮常驻会话（Session），上下文体积会以滚雪球的形式急剧膨胀：
- **前轮输出变成下轮输入**：模型说过的每句话、跑过的每个长日志，下一轮都需要原封不动全量上传；
- **粗暴截断（如手动 `/clear`）的局限**：这在产品哲学上是系统的失职。用户被迫在“被 Token 撑爆”与“瞬间失忆”之间做痛苦的二选一。

---

## 二、架构突破：双层全自动上下文治理体系

不同于传统方案的单一手段，我们构建了一套“微观防暴击 + 宏观抗衰老”的双层协同流水线：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        双层自动上下文治理流水线                           │
└────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
       【第一层：微观/即时脱水（Per-turn Tool Pruning）】
       • 触发时机：每一轮任务刚执行完毕的瞬间
       • 治理目标：消除单次大命令暴击（如 git log、cat 大文件）
       • 动作：本轮需要看全量细节；但任务一结项，立即把历史中臃肿的 tool_result
               自动折叠为状态标记（实测单轮即挤掉 1.3KB 冗余文本），只留干货。
                                    │
                                    ▼
       【第二层：宏观/滚动蒸馏（Multi-turn Rolling Compaction）】
       • 触发时机：当会话累计 Token 或轮次达到警戒线（如消息数 ≥ 6）
       • 治理目标：化解多轮聊天的慢火膨胀
       • 动作：后台静默调用一次模型，将早期琐碎对话浓缩为一份高纯度的
               【核心事实备忘录 (Memory Ledger)】置于头部，无缝衔接最新轮次。
                                    │
                                    ▼
       【实测验证结果】：四轮长任务后，用户身份、核心目标、历史提交记录等
                      关键信息 100% 无损传承，同时上下文消息数被压制在健康区间！
```

## 三、“永不遗忘”的规则：系统提示词 vs AGENTS.md

在上下文压缩的过程中，必须确保最高规范永不漂移、永不被稀释。我们确立了规则分层的黄金法则。

### 黄金判定法则：“隔壁朋友测试法”
> **“如果把这个 Harness 打包送给隔壁写 Python 或做前端的朋友用，这条规则对他还有用吗？”**
> - **依然有用 / 必须有** $\longrightarrow$ **写在代码里（System Prompt）**
> - **只适用于具体项目或个人** $\longrightarrow$ **写在工作区文件里（`AGENTS.md`）**

### 对比清单速查：

| 维度 | 代码内置（System Prompt） | 工作区文件（`AGENTS.md`） |
| :--- | :--- | :--- |
| **定位** | **员工的“出厂设置 / 职业操守”** | **项目的“规章制度 / 团队守则”** |
| **决定者** | Harness 架构师 | 具体项目开发者 / 仓库维护者 |
| **典型内容** | 运行环境（OS、CWD、日期）、工具调用安全底线、报错自愈指导、终端交互协议 | 框架选型（Vue3/React）、代码规范（禁用的 API）、测试验收命令、个人称谓偏好 |
| **版本控制** | 随 Harness 软件版本发布 | 随业务项目代码库（Git）流转 |
| **修改频率** | 极低（发布后固定） | 随时随地按需修改 |

## 四、代码落地产出

1. **`src/context-manager.ts`**：实现了 L1 脱水（`dehydratePriorToolOutputs`）与 L2 自动滚动蒸馏（`compactSessionIfNeeded`）；
2. **`src/loop.ts`**：升级为带状态会话引擎（`AgentSession`），实时追踪 Token 消耗并在关键切面自动介入治理；
3. **`src/test-governance.ts`**：端到端 4 轮严苛测试，验证脱水与记忆备忘录在长任务下的有效性。
