# 第一讲复盘：从直觉、质疑到刺穿真相的探索之旅

> "知识不是被灌输的，而是在一次次'Hold on'、质疑与亲手验证中生长出来的。"

本篇文档记录了我们在构建专属 Agent Harness 旅程中，第一阶段（基础篇）真实发生的思想碰撞、关键质疑与认知升级。

---

## 阶段足迹：那些改变走向的关键对话

### 1. 穿透繁复的直觉：“LLM 既不能当运动员，又当裁判”
- **初次疑问**：在很多教程把 Agent 包装得神乎其神时，你提出了最质朴也最致命的质疑：
  > *“第一件事是不是先调用 LLM，然后把上一步的输出作为输入做循环？而且必须有达成目标的判断标准，不能让 LLM 既当运动员，又当裁判！”*
- **认知沉淀**：
  - 这句话切中了所有 Agent 的底层物理事实：**LLM 没有手脚，物理上只是一次次被动的 HTTP POST**。
  - “运动员与裁判不能是同一人”：如果把“做没做完”的裁决权全部交给 LLM 本身，Agent 必然陷入自欺欺人的幻觉与死循环。真正的 Harness 必须掌握**外部客观裁决权**（退出码、编译器检查、独立验证器）。

---

### 2. 跳出程序员视角的洞察：“通用场景如何验收？”
- **认知分歧**：AI 一度陷入纯程序员视角（语法树、单元测试、TSC 编译），你及时将其拉回现实：
  > *“我本职不是程序员，我更看重非编程场景的实现。当用户没有明确验收条件时，是否在执行前就该让 LLM 分析提炼出验收标准？”*
- **认知沉淀**：
  - 由此推导出了工业级 Agent 必须具备的 **两阶段交付契约（Deliverable Contract）**：
    - 在真正动手乱动文件之前，先生成人类可读的 **Checklist（验收清单）**；
    - 不管是整理下载目录，还是撰写分析报告，物理交付物是否存在、关键要素是否齐备，是 Harness 衡量目标达成的重要尺子。

---

### 3. 最宝贵的一次刹车：“Hold on，我们是不是进展过快了？”
- **转折时刻**：当讨论迅速滑向高级概念（双 Agent 裁判、子系统）时，你敏锐地踩下了急刹车：
  > *“Hold on，我有点担心我们这样是否进展过快了，以至于中间是否漏掉了什么？”*
- **认知沉淀**：
  - **这一脚刹车是全场最精彩的转折点**。它阻止了盲目的“概念自嗨”，让我们果断剥离掉所有花架子，退回到最朴素的原点——回到最单纯的单次 API 请求。

---

### 4. 敏锐的协议洞察：“还有一个 Responses 格式”
- **认知深挖**：在对比常见的 OpenAI Chat 和 Anthropic Messages 时，你指出了极易被忽略的前沿趋势：
  > *“你只是提到了 Anthropic 和 ChatGPT，但是没有说 responses 格式啊。使用 responses 格式的话，那就要求 LLM 供应商有这个能力支持状态，否则会不会比 chat 格式更差？”*
- **认知沉淀**：
  - 你一眼看破了服务端有状态协议的“双刃剑”效应：
    - **无状态（Stateless）** 赋予客户端 100% 的掌控权，容灾能力最强；
    - **有状态（Stateful）** 极度依赖服务端的存储与会话架构，一旦中转或后端不支持，直接沦为残废。

---

### 5. 动手刺穿真相：“直面真实的中转网关与 VPS 实战”
- **现场实测**：直接拿你自建的中转服务 `https://webdav.317316.xyz/v1/responses` 验证：
  - 第一轮告诉它秘密代号；
  - 第二轮带 `previous_response_id` 提问；
  - **真相大白**：底层 Gemini 果然完全无记忆！
- **不满足于理论，动手解决它（路径 B）**：
  - 登入 VPS，解构 `CLIProxyAPI` 源码，证实其对 Gemini 请求确实丢弃了 `previous_response_id`；
  - 在 VPS 上部署专属的 `stateful_gateway.py`（Python aiohttp + SQLite）；
  - **践行你的要求**：配置 24 小时 TTL 与每 10 分钟自动清理循环（`incremental_vacuum`），杜绝数据库膨胀；
  - **最终结果**：端到端验证通过，模型成功记住了“天王盖地虎”与密码计算！

## 核心技术沉淀：三大 API 协议一览

```
                     ┌── 1. OpenAI Chat (/v1/chat/completions) ── 无状态，开源默认，role="tool" 补丁
                     │
原始 HTTP POST ──────┼── 2. Anthropic Messages (/v1/messages) ─── 无状态，块级模型（Pi 的基石）
                     │
                     └── 3. OpenAI Responses (/v1/responses) ──── 有状态设计，需服务端或 Harness 代理记账
```

1. **状态的本质**：服务端所谓的“状态”，不过是有人在数据库里替你暂存了一份 `messages` 数组。
2. **Harness 的主权**：
   - 依赖服务端状态，你将丧失灵活的回退（Rewind）、分叉（Branching）与手动压缩（Compaction）能力；
   - 掌控客户端无状态，你的 Harness 才能成为真正属于你自己的操作系统。
