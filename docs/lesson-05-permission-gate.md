# 第五讲复盘：安全气囊与刹车系统（Permission Gate 权限拦截门）

> “方向盘让马车跑在正确的路上，而刹车保证了在万丈深渊前，马车能绝对停下。”

本篇文档记录了我们在第五阶段中，为 Harness 打造 **三级权限拦截闸门（Permission Gate）** 的完整设计哲学、技术实现与实战演练。

---

## 一、为什么需要“智能分级”的刹车？

如果刹车设计得粗暴，往往会导致两种极端：
1. **“狼来了”式的全面瘫痪**：每读一行代码、每看一个目录都弹一次弹窗问用户“是否允许”，用户几分钟就会被烦死，闭着眼一路按 Yes，安全机制彻底形同虚设；
2. **“裸奔”式的全面失控**：完全不设防，模型一个手抖或者陷入幻觉，执行了 `rm -rf` 或覆写了 `.env` 密钥，造成不可挽回的灾难。

因此，**真正的工业级 Harness 必须具备“三级安全光谱判定（Three-Tier Security Spectrum）”**！

---

## 二、Permission Gate 三级安全光谱

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        Harness 权限拦截闸门光谱                         │
├───────────────┬──────────────────────────────────┬─────────────────────┤
│ 1. 绿色安全级  │ • 只读文件 (read_file)           │ 物理静默，自动放行    │
│    (SAFE)     │ • 只读命令 (ls, git status, pwd) │ 不打扰用户喝咖啡     │
├───────────────┼──────────────────────────────────┼─────────────────────┤
│ 2. 黄色敏感级  │ • 修改/新建常规源码文件           │ 弹出授权申请         │
│    (SENSITIVE)│ • 执行常规构建/非只读命令        │ 支持 [y] 批准一次   │
│               │                                  │ 或 [a] 本会话信任   │
├───────────────┼──────────────────────────────────┼─────────────────────┤
│ 3. 红色高危级  │ • 不可逆删除 (rm -rf, dd, kill)  │ 刹车绝对咬死！       │
│   (DANGEROUS) │ • 触碰机密路径 (.env, .ssh, .git) │ 即使会话信任也必须审 │
└───────────────┴──────────────────────────────────┴─────────────────────┘
```

## 三、现场实测全景复盘

在 `src/test-permission.ts` 的端到端测试中，涵盖了三个最真实的场景：

### 场景 1：安全只读（丝滑放行）
- 用户指令：“查看 package.json 前 5 行”；
- 判定结果：`read_file` 命中 `SAFE` 级别；
- **Harness 表现**：毫无卡顿、完全静默自动执行，秒速返回前 5 行内容，不产生任何无谓的弹窗骚扰。

### 场景 2：不可逆高危破坏（刹车咬死 + 用户否决）
- 用户指令：诱导执行 `bash: rm -rf dist/`；
- 判定结果：命中 `DANGEROUS` 级别（正则匹配到递归强制删除）；
- **Harness 表现**：
  - 闸门立即挂起执行，终端高亮亮起红色警报并展示完整参数；
  - 模拟用户审核后按下 `n` 拒绝；
  - Harness 拦截掉真实 Shell 执行，并回传一条权威拒绝：“`Permission Denied: 用户在审核后明确拒绝了此操作`”。
- **Agent 自愈反应**：
  - 模型不仅没有报错崩溃，反而极其体面地向峰哥复命：“`rm -rf` 已被安全拦截，已按要求放弃直接删除该目录，请手动处理。”

### 场景 3：敏感修改与人类授权放行
- 用户指令：使用 `write_file` 创建备忘文件；
- 判定结果：命中 `SENSITIVE` 级别；
- 用户按下 `y` 放行；
- 文件安全落盘，流程闭环！
