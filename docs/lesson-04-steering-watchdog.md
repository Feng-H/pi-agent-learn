# 第四讲复盘：双轨方向盘（自动车道保持看门狗 + 随时人工插话 Steering）

> “真正的自动驾驶不是让人死盯着屏幕随时踩刹车，而是哪怕人不在电脑前，系统也能自动识别死胡同并当头棒喝拉回车道。”

本篇文档记录了我们在第四阶段中，针对“用户不可能一直盯着屏幕输出”的痛点，设计并落地 **双轨方向盘系统（Steering Watchdog）** 的完整心路与技术实测。

---

## 一、核心痛点：为什么不能依赖“人工实时盯盘”？

传统 Agent 的交互设计常常存在一种“不切实际的假设”：假设用户像监工一样坐在屏幕前，一看到模型跑偏就敲快捷键打断。
**现实真相是**：
- 用户把任务交给 Agent，就是为了离开屏幕去喝咖啡或干别的；
- 等用户回过头来看屏幕时，往往发现模型早就在前 3 步走进了死胡同，把剩下的 7 步全浪费在反复试错上，徒劳烧掉了上万 Token。

因此，**Harness 必须具备代替人类“自动发现偏航并强制纠偏”的能力**！

---

## 二、双轨方向盘架构设计

```text
┌─────────────────────────────────────────────────────────────────────────┐
│                      Harness 双轨方向盘 (Steering Engine)                │
├───────────────────────────────────┬─────────────────────────────────────┤
│ 轨道 A：自动车道保持 (Watchdog)    │ 轨道 B：人工随时介入 (Human Queue)    │
│ （面向：用户不在电脑前的 90% 场景） │ （面向：用户恰好看到想纠偏的 10% 场景）│
├───────────────────────────────────┼─────────────────────────────────────┤
│ • 自动检测“鬼打墙”（完全重复操作） │ • 终端非阻塞接收人类插话             │
│ • 自动检测“硬撞南墙”（连续 2 次报错）│ • 优先级别最高，直接覆盖自动检测     │
│ • 触发后强行拦截下一条命令，        │ • 强行改道，顺从人类指挥官最新意志   │
│   注入【当头棒喝警报】逼迫模型反思  │                                     │
└───────────────────────────────────┴─────────────────────────────────────┘
```

## 三、现场实测精彩复盘

在 `src/test-steering.ts` 的端到端测试中，两个场景的运转极具戏剧性：

### 场景 1：自动看门狗当头棒喝（人不在电脑前）
1. 用户下达了一个包含不存在路径的迷惑性任务；
2. 模型第 1 步尝试读取 `src/no-such-config.json`，报错不存在；
3. 模型第 2 步尝试读取 `src/non_existent_fallback.json`，再次报错不存在；
4. **此时看门狗瞬间咆哮**：
   > `⚠️ [看门狗拉响警报] 模型已连续 2 次执行报错，硬撞南墙！`  
   > `🛡️ [Harness 方向盘介入] 向模型强制注入纠偏指令！`
5. **模型反应**：
   收到警报后，模型立刻停止了盲目猜文件，改用 `ls` 扫描目录实地考察；随后不仅完成了详尽的失败反思，还为用户梳理出实际存在的根目录配置文件清单！

### 场景 2：人工随时中途插嘴（人在电脑前）
1. 用户在模型执行中途塞入了一句插话：`"不用找那个 json 了，其实配置在 package.json 里面"`；
2. **Harness 瞬间响应**：
   > `🚨 [人工握紧方向盘] 检测到用户中途介入指令！`  
   > `🛡️ [Harness 方向盘介入] 向模型强制注入纠偏指令！`
3. 模型立马放弃原有的检索逻辑，乖乖调取 `package.json`，秒速提取出项目元数据汇报给峰哥！

## 四、代码产出与沉淀

1. **`src/steering.ts`**：实现了 `SteeringWatchdog` 类，内置死循环检测、连续报错追踪与人工指令队列；
2. **`src/loop.ts`**：在内层 ReAct 循环中将看门狗作为每一步前置的“安全员”，实现毫秒级偏航拦截；
3. **`src/test-steering.ts`**：自动化模拟了硬撞南墙自愈与人工中途插嘴两大典型场景。
