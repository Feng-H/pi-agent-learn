## 一、核心心智模型：什么是真正的“Harness（挽具）”？

很多人把大模型当成了某种无所不能的生命体。但物理现实极其冰冷：
- **LLM 物理本质**：只是一个被动的、无状态的“文本接龙预测器”，物理上只是一次次 HTTP POST 请求。它既没有手脚，也没有记忆，更没有执行任何命令的权限。
- **Harness 的角色**：套在大模型这匹烈马嘴上的嚼子、缰绳、底盘与仪表盘。
  - **马负责奔跑**（提供推理与生成文字）；
  - **Harness 负责控制一切**（拦截意图、替它在操作系统中执行工具、组织记忆生命周期、防止它撞墙暴毙、并在万丈深渊前死死踩住刹车）。

### 阶段零与一：物理地基与核心心脏

#### 1. 裁判权归属的哲学之问
> *“LLM 不能既当运动员，又当裁判。”*
- **初学者的陷阱**：让 LLM 自己判断任务完没完成。结果是模型改错了代码、单元测试挂了，它却在文本里自欺欺人“已为您修复完成”，系统草草收场退出。
- **Harness 的立足点**：Harness 必须握有外部客观裁决权（命令 Exit Code、编译器状态、测试结果、人类确认）。

#### 2. 三大 API 协议的透视与 VPS 实战
- **OpenAI Chat (`/v1/chat/completions`)**：无状态，最通用，工具调用作为聊天的一种附带格式；
- **Anthropic Messages (`/v1/messages`)**：无状态，Pi 的最爱，纯粹的 Content Block 块结构；
- **OpenAI Responses (`/v1/responses`)**：面向 Agent 的下一代有状态设计。
- **实战刺穿**：
  - 实测发现中转网关对 Gemini 的 `/v1/responses` 仅有接口外壳、实质并无跨请求状态记忆；
  - 登入 VPS，编写并部署 `stateful_gateway.py`，用 SQLite（配置 24 小时 TTL 与每 10 分钟 `incremental_vacuum` 自动清理）真正打通了服务端的连续状态记忆链！

### 阶段二：长上下文治理与规则金字塔

#### 1. 拒绝粗暴人工截断，构建双层全自动治理
当会话从单次交互走向多轮（Session）后，Token 呈现滚雪球式暴增。我们拒绝靠打 `/clear` 粗暴格式化记忆，而是建立了**微观防暴击 + 宏观抗衰老**双层防线：
- **L1 微观工具脱水**：单轮任务结算的瞬间，自动扫描历史中的臃肿 `tool_result`（如长篇 `git log`），折叠为轻量标记，单轮实测挤掉 1.3KB 冗余，保护后续轮次不被暴击；
- **L2 宏观滚动蒸馏**：消息数跨越警戒水位线时，后台静默将早期对话提炼为一份结构化的【系统长期记忆备忘录（Memory Ledger）】，老旧消息蒸发，核心事实永久保留。

#### 2. “永不遗忘”的规则金字塔与“隔壁朋友测试法”
如何防止模型在多轮对话中规则漂移、忘记规矩？
- **代码内置（System Prompt）**：环境自知（操作系统、路径、日期）、工具安全礼仪。
  - *判定标准*：打包送给隔壁写不同语言的朋友，这条规则对他依然必须。
- **工作区文件（`AGENTS.md`）**：具体项目的代码技术规范、测试验收要求、用户个人称谓偏好（“峰哥”）。
  - *判定标准*：仅对当前仓库和当前团队有效，可随时随 Git 提交修改。

### 阶段三：打造灵巧双臂——Pi 风格文件工具箱

破除“一个 `bash` 走天下”的转义字符地狱与上下文防爆风险，复刻 [pi.dev](https://pi.dev) 的核心武器库：
1. **`read_file`**：带行号（1-based）、强制支持局部切片（`offset` / `limit`），杜绝一口吃爆上下文；
2. **`write_file`**：带目录自动递归创建（`mkdir -p`）的原子写入；
3. **`edit_file`（Harness 的灵魂）**：精准局部字符串替换，三重防错防歧义（存在性核查、唯一性核查、防相同替换），告别整文件重写的巨额 Token 浪费与丢代码风险；
4. **实测大捷**：Agent 遵守 `AGENTS.md`，自主阅读有 Bug 的计算器源码，精准用 `edit_file` 单行替换修复，跑测通过并体面交付！

### 阶段四：智能方向盘——双轨纠偏体系

#### 破除“人肉盯盘”的伪需求假设
用户找 Agent 干活是为了离开屏幕去喝咖啡，不可能一直死盯屏幕。因此 Harness 必须具备**自动车道保持能力**：
- **看门狗（Watchdog）全自动巡航**：
  - 检测到“鬼打墙”（连续两次完全重复操作）或“硬撞南墙”（连续两次报错）；
  - Harness 亲自下场，强行拦截下一次盲目调用，注入【当头棒喝警报】逼迫模型复盘反思、主动改道；
- **随时人工插话通道**：
  - 非阻塞式插话队列，用户一旦在终端输入提示（如“看 package.json”），立即以最高优先级接管方向。

---

### 阶段五：安全刹车——三级安全光谱权限门

方向盘负责指路，刹车负责保命。为了杜绝“狼来了”式的全量弹窗骚扰与完全不设防的破坏风险：
- **`SAFE`（绿灯放行）**：`read_file`、`ls`、`git status` 等只读探针，完全静默自动执行，不打扰用户；
- **`SENSITIVE`（黄灯请示）**：常规源码修改、构建命令，弹出参数卡片，支持 `[y]` 批准一次或 `[a]` 本次会话全局信任；
- **`DANGEROUS`（红灯咬死）**：`rm -rf`、修改 `.env` 或 `.git/`，即使处于全信任模式也必须逐一核准；
- **实测验证**：下达危险删除指令，人类按 `n` 否决，模型被拦截后不仅不崩溃，反而自主放弃破坏并客观汇报替代方案。

---

### 阶段六：工业级防线硬化与 CMU 11-768 对标

在真实生产环境中，微小的协议不一致或命令前缀死角会导致整个系统崩溃。我们对标 **CMU 11-768 (AI Agents) Assignment 1 · Harness** 进行了工业级硬化：
1. **消息管线规范器（`normalizeMessages`）**：
   - 严格维护大模型交替状态机，自动合并同角色连续消息（解决警报独立推送到 user 导致的 400 错误）；
   - 自动检测并降级孤儿 `tool_result`，防止切片导致上下文坏死；
2. **工具感知差异化脱水**：
   - `read_file` 源码建立绝对保护，禁止粗暴截断，确保模型后续调 `edit_file` 时上下文绝对保真；
   - 专攻 `bash`、`git log` 等终端膨胀日志进行轻量折叠；
3. **Shell 语法树原子拆分防逃逸**：
   - 废除单薄的字符串前缀匹配，按 `&&`、`||`、`;`、`|`、`>` 拆分子命令；
   - 封死 `echo 'hello' && rm -rf /` 或重定向写 `.env` 等逃逸后门；
4. **单进程事件循环非阻塞实时插话**：
   - 在终端多轮 REPL 运行中实现事件级监听，模型跑工具时人类随时敲回车输入指令，实时送入看门狗纠偏。
